# Verification: The Hidden Channel Keeps Off the Game's Channel Numbers

The code built on assumptions only the game can confirm carries `-- VERIFY(<id>): <what>`; the IDs continue the V
series (V69 was spec 020's; this spec has V70 to V74). A marker is removed after the author confirms the behaviour in game, or when the author
accepts the assumption without a check (the row then says "Accepted" and what happens if it is wrong).

Already seen in game (2026-11-22, [research.md](research.md)), no marker: a join gets the lowest free number;
General's number is free while the player is not in General; a typed
`/run C_ChatInfo.SwapChatChannelsByChannelIndex(1,7)` trades two numbers; a `/reload` keeps the numbers; a login does
not bring the temporary channel back.

To close an item: run its check, record the answer in `docs/forever-api.md`, adjust the code if the game differs,
remove the marker and tick the item here. Every command below is under 255 characters. The list of channels is
`/run for i=1,20 do local n,s=GetChannelName(i) if n>0 then print(n,s) end end`.

The broken order for V70 and V71: turn "Use the public channel" off, `/leave 1`, turn it on, `/join General` (the
channel on 1, General on 7). With a build of this branch the addon repairs it by itself, so run these two with
1.5.0 or with the addon's repair already stopped.

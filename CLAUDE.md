# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

OneKeyFishing is a World of Warcraft addon for **WoW Forever** (Interface `16001`, build 1.60.1, `WOW_PROJECT_ID = 18`), published under the MIT license. The Forever client runs the modern (Mainline) API, not the Classic one. The game client can run in any language, so game data is matched **by ID, never by name**. The addon's own interface is English; every visible text goes through `ns.L` (see Locales below). Everything in the repository is written in English.

Hard rule: the addon must stay within Blizzard's UI Add-On Policy. Every game action (cast, hook, use item) happens on a real key press through secure buttons and override bindings. No automatic reaction to the bobber splash, no external tools.

Docs: `README.md` (players), `CHANGELOG.md`, `docs/ROADMAP.md` (future features), `docs/publishing.md` (release steps and the policy checklist), `docs/publishing-plan.md`, `docs/history/mvp-plan.md` (the original plan and the API spike results).

## Commands

The addon lives in `OneKeyFishing/` (exactly what goes into `Interface/AddOns`: the TOC, Lua files, `Bindings.xml`, `Locales/`, `UI/`); `tools/`, `tests/`, `docs/` and project files stay in the repository root. Paths below such as `Core.lua` or `Locales/enUS.lua` are inside `OneKeyFishing/`. The tools need Node.js 18+ (`npm install` once):

- `npm run check`: the addon folder holds only packaged files (TOC-listed + `Bindings.xml`), Lua 5.1 syntax, undeclared **and unused** globals against `.luacheckrc`, lines up to 120 characters, ASCII-only Lua/TOC/XML files, no Cyrillic anywhere, Lua files only in `OneKeyFishing/` and `tests/` (test files get the syntax and line-length checks), every Lua file listed in the TOC, locale keys in sync, and `package.json` version == newest `CHANGELOG.md` entry. Run it after every change. A new WoW API global goes into `.luacheckrc` `read_globals`.
- `npm test`: the Lua tests in `tests/` (`npm test -- lures` runs only matching files). `tests/run.mjs` runs every `tests/*_test.lua` in a fresh fengari state after `tests/wow.lua`, which holds the WoW API stubs (frames, events, a controllable clock and timers, configurable bag item counts, cooldowns, prices, loot) and the helpers (`test`, `eq`, `near`, `fire`, `advance`, `tick`, `click`, `load_addon`, `load_files`). Unknown globals are permissive stubs. Run it after every change; add or extend a test when changing logic that can run without the game (Core, Bags, Catch, Stats, the statistics window). fengari is Lua 5.3, the game is 5.1: keep the addon free of 5.1/5.3 differences, and fix a test that fails only because of 5.3 in the test or the stub.
- `npm run dev`: packages the working folder into `dist/OneKeyFishing/` and `dist/OneKeyFishing-<version>.zip` (version `x.y.z-dev+<commit>`).
- `npm run build`: refuses uncommitted changes, runs check and test, then packages the last commit.
- `npm run link` / `npm run unlink`: link `Interface/AddOns/OneKeyFishing` to `OneKeyFishing/` (a junction on Windows) for development without building; the unbuilt version shows as `dev`.
- `npm run install-addon`: `dev`, then copy into the game's AddOns folder. `link`, `unlink` and `install-addon` read `WOW_ADDONS_DIR` from the environment or a git-ignored `.env` (see `.env.example`), and refuse anything that is not `.../Interface/AddOns` or that contains the repository. A new file or a TOC change needs a game restart, not just `/reload`.
- The package contains only the TOC, the files it lists and `Bindings.xml` from `OneKeyFishing/`, plus `LICENSE`, `README.md` and `CHANGELOG.md` from the root (`tools/addon.mjs`). `## Version: @project-version@` is filled in at build time; `package.json` holds the version.
- Releases: a pushed tag equal to the version (`1.0.0`) runs `.github/workflows/release.yml` (BigWigsMods/packager with `.pkgmeta`, whose `move-folders` makes `OneKeyFishing/` the package).
- Claude cannot run the game, so in-game testing is always handed to the user with a checklist. In game: `/okf` lists commands; `/okf debug` shows the state report used in bug reports.

## Architecture

All files share the addon namespace (`local _, ns = ...`). Load order is the TOC order; a module may only call another module at runtime, not at file load time, unless it comes earlier in the TOC.

- **Locales/enUS.lua** (loaded first): `ns.L`, keyed by the English text and falling back to the key. Every `L["..."]` in the code must be listed there and vice versa (`npm run check`). Use literal keys only (`L["text"]`, never `L[a .. b]`) and keep color codes outside the strings. A translation is a `Locales/<locale>.lua` file after `enUS.lua` that sets `L[english] = translation` when `GetLocale()` matches. The debug report is deliberately not localized.
- **Core.lua**: `ns.RegisterEvent` (several handlers per event), the internal message bus `ns.On` / `ns.Fire`, saved variables (`Migrate` runs `MIGRATIONS` up to `DB_SCHEMA`, then `ApplyDefaults` fills missing keys without overwriting; bump `DB_SCHEMA` and add a migration whenever a saved field is renamed, moved or reshaped), slash commands (`ns.RegisterCommand`, `/okf` and `/onekeyfishing`), `ns.version` from the TOC, and binding labels. `OneKeyFishingDB` holds account-wide data (settings, fished item IDs, auction prices, positions); `OneKeyFishingCharDB` holds per-character data (fishing gear, statistics, and pending restore state).
- **Action.lua**: the single fishing key. Keys bound to `ONEKEYFISHING_ACTION` (Bindings.xml) are overridden only while the mode is on. When the player is not channeling, the key clicks `OneKeyFishingButton` (SecureActionButtonTemplate). Its `PreClick` resolves the action by priority: apply lure, then open a fished container, then cast Fishing. While channeling Fishing, the key is bound to `INTERACTTARGET` (soft-target interact hooks the bobber). The overrides are owned by a `SecureHandlerStateTemplate` frame whose `[combat]` state driver clears them inside combat.
- **Mode.lua**: enter and exit fishing mode. Every changed CVar, the gear swap, the camera zoom and a `resumeMode` flag are stored in the character DB *before* changing anything. As a result, exit, logout, `/reload` (which also fires `PLAYER_LOGOUT`) and crashes all restore correctly. After `/reload` the mode resumes after a 1 second delay, because bindings and the spellbook are not ready on `PLAYER_ENTERING_WORLD`.
- **Gear.lua**: equips the chosen pole (or the best pole by fishing bonus) plus user-picked extra items. It records only the slots it changed (`charDB.gearSwap`). On exit a slot is restored only if it still holds what the addon put there. The fishing bonus is parsed from tooltip lines that contain the client's localized Fishing spell name minus its first UTF-8 character (tooltips may lowercase it, and `string.lower` only handles ASCII). Weapons return immediately in combat; the rest waits until combat ends.
- **Bags.lua**: lures and fished containers. A container's loot window is matched to the open attempt by the item GUID (`GetLootSourceInfo`); nothing is opened over an open loot window; a container whose loot did not fit waits for free bag space, a locked one is skipped for the session. `ns.ForEachBagItem` (Data.lua) is the shared bag iterator.
- **Catch.lua** turns casts and loot into `FISH_CAUGHT` / `FISH_MISSED` messages. **Stats.lua**, **UI/Toast.lua** and **Skill.lua** consume them. Stats counts time in segments (fishing mode on, optionally not AFK) and flushes them on zone change and logout. It keeps per-session, per-zone and total buckets; the item value is computed at read time through **Prices.lua** (the higher of the vendor and the scanned auction price). **Auction.lua** runs one `C_AuctionHouse.SendSearchQuery` at a time, with throttle retry and timeout.
- **UI/**: Indicator (next action, cast bar, session timer, "No bobber" when the soft interact GUID is not game object 35591), Settings (canvas pages built from plain widgets, not the Settings setting-type API), StatsFrame, Minimap (the button and the Addon Compartment entry from the TOC), ItemHooks (Alt+Click on items through `HandleModifiedItemClick`, plus a tooltip line), CopyWindow. **Debug.lua** builds the `/okf debug` report.

## Known API facts for Forever (verified in game)

- `INTERACTTARGET` exists. The bobber is readable as unit `softinteract` (name and GUID), but it has **no nameplate** and `UnitExists` is false, so nothing can be anchored to it.
- Fishing rank spells are 7620 / 7731 / 7732 / 18248. The skill comes from `GetProfessions()` → `GetProfessionInfo` (skillLine 356); `GetSkillLineInfo` does not exist.
- These are missing: `GetSpellInfo`, `GetItemInfo`, `EquipItemByName` and the classic auction API. Use `C_Spell`, `C_Item`, `C_Item.EquipItemByName` and `C_AuctionHouse` instead.
- `C_Item.EquipItemByName` fails silently while casting or channeling, so a gear swap entry is only cleared on `PLAYER_EQUIPMENT_CHANGED`, and a restore during a cast waits for the cast to end.
- Bags cannot be opened while the Settings panel is open, so items are added through Alt+Click in bags, not from the panel.
